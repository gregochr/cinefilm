### Changed — credits classifier: the evaluation reads films one at a time and reads model B's model files (L4b-6a)

`FeatureRunReader.forEachFilm` hands each film of `features.csv` to a sink as soon as its last row is read, with the checks `read` has (`read` is now `forEachFilm` collecting into a list). `CreditsEvaluateJob` uses it: a development film's predictions are computed as it arrives, and a test film keeps, for each run, the mean of that run's five shipping models' predictions, so after `chooseFinal` the final run's entry is scored and no film's rows are held past its scoring inputs. The output files are byte-identical to before. `FrameModel` is a sealed interface (`base()`) that `GradientBoostedTrees` and `LogisticRegression` implement. `TrainedRun.load` reads `model.json`'s `type`: `"gbt"` as before, `"logreg"` through `LogisticRegression.fromJson` (keeping the encoder's `sha256` and `dimension` and `embeddingsDevSha256`), anything else, or no type, refused. An evaluation refuses, before it creates any directory, training runs of more than one type and any `"logreg"` run (until L4b-6b adds `--embeddings`). Tests pin each of these, including test films scored by the final run's shipping models whichever place it has in the list.
