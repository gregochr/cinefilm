### Added — credits classifier: the evaluation scores model B (L4b-6b)

`CreditsEvaluateMain` takes `--embeddings <embeddings run>` and now evaluates model B's `"logreg"` training runs (one model type per evaluation, as before). `EmbeddingCursor` reads `embeddings.bin` in step with `FeatureRunReader.forEachFilm`: for each film it returns the next `coarse + dense` records as that film's embeddings, checks each record's key against its `features.csv` row, and holds only one film's embeddings at a time. A frame's `p` is NaN when its row has no time features, exactly as for model A, and otherwise the `LogisticRegression` on its embedding; the evaluation's segmenter, calibration and output files are unchanged, and model A's output is byte-identical. The tool refuses, with exit 1 and nothing written: `"logreg"` runs without `--embeddings`, `--embeddings` with `"gbt"` runs, an embeddings run whose `featuresCsvSha256`, `datasetSha256`, `labelsSha256` or `featureVersion` is not the features run's, a run whose encoder `sha256` or `embeddingsDevSha256` is not the embeddings run's (so model B is scored on the embeddings it was trained on), an encoder or `embeddings.bin` of another dimension, `--look=L5` with an embeddings run that has no `look.json`, a record whose key is not its row's, and a record count other than the row count. Tests cover a B-only evaluation with every output file pinned, a dense row with no time features, each refusal, test films scored by the final run's shipping models under `--look=L5`, the one-film seam, and a model B run written by `CreditsTrainLrJob`, read back through `TrainedRun.load` and evaluated end to end.
