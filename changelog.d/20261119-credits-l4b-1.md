### Added — credits classifier: the ONNX image encoder (L4b-1)

The first code of model B (the embeddings model). `EncoderSpec` reads an encoder's `encoder.json` and checks the ONNX file's SHA-256 and that its input is the 224-pixel square the stored frames are; `EncoderInput` turns pictures into the normalised tensor; `ImageEncoder` is the interface and `OnnxImageEncoder` runs the model on ONNX Runtime (one thread, sequential, no CPU arena), refusing a model without the named input and output and an output of the wrong shape or with a NaN or infinite value. A tiny ONNX file (the mean of each colour channel) and the test-source class that writes it let every part be tested with exact values. Nothing in the server calls any of it yet. The ONNX Runtime library (1.31.1, about 49 MB with its natives) is now in the image; the server never loads it before the product phase. ONNX Runtime ships no macOS Intel natives, so `OnnxImageEncoder` is tested on Linux in CI only and is left out of the local coverage check.
